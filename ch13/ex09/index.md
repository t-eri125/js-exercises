## 問題 13.9 💻🖋️

以下の各関数を実行すると何が出力されるか予想し実際に確認しなさい。
またその理由を 2、3 行のテキスト、図のいずれかまたは両方で説明しなさい。テキスト・図は問題 13.2 を参考にしなさい。
`i4` に関しては、コードを修正して `v` の最終結果が 10 となるコードを実装しなさい。

## 回答
### i1()
#### 回答

`1秒後に 42 が出力され、さらに2秒後に 42 が出力される`

#### 説明

v が上書きされる副作用を見逃していた。
`1秒後に 42 が出力され、さらに2秒後に 100 が出力される`

```
log(v) で wait1() と wait2() が同時に実行開始し、先に wait1() が解決して 42 を返す。
ここで any 自体は完了し、裏で非同期処理は続く。
しかし、wait2() の解決時に、Promise とは無関係に外部変数 v が 100 に上書きされるため、2回目の log(v) で 100 が出力される。
```

メモ

- 最初のプロミスが履行された後は短絡的に処理するので、一つを見つけると、他のプロミスが完了するのを待つことはありません。
[参考：MDN](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Promise/any#:~:text=%E6%9C%80%E5%88%9D%E3%81%AE%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%8C%E5%B1%A5%E8%A1%8C%E3%81%95%E3%82%8C%E3%81%9F%E5%BE%8C%E3%81%AF%E7%9F%AD%E7%B5%A1%E7%9A%84%E3%81%AB%E5%87%A6%E7%90%86%E3%81%99%E3%82%8B%E3%81%AE%E3%81%A7%E3%80%81%E4%B8%80%E3%81%A4%E3%82%92%E8%A6%8B%E3%81%A4%E3%81%91%E3%82%8B%E3%81%A8%E3%80%81%E4%BB%96%E3%81%AE%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%8C%E5%AE%8C%E4%BA%86%E3%81%99%E3%82%8B%E3%81%AE%E3%82%92%E5%BE%85%E3%81%A4%E3%81%93%E3%81%A8%E3%81%AF%E3%81%82%E3%82%8A%E3%81%BE%E3%81%9B%E3%82%93%E3%80%82)

- 先に拒否されたプロミスがあったとしても、最初に履行されたプロミスで解決されます
[参考：MDN](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Promise/any#:~:text=%E5%85%88%E3%81%AB%E6%8B%92%E5%90%A6%E3%81%95%E3%82%8C%E3%81%9F%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%8C%E3%81%82%E3%81%A3%E3%81%9F%E3%81%A8%E3%81%97%E3%81%A6%E3%82%82%E3%80%81%E6%9C%80%E5%88%9D%E3%81%AB%E5%B1%A5%E8%A1%8C%E3%81%95%E3%82%8C%E3%81%9F%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%A7%E8%A7%A3%E6%B1%BA%E3%81%95%E3%82%8C%E3%81%BE%E3%81%99)


### i2()
#### 回答

`1秒後に C が出力され、その1秒後に B が出力され、さらに1秒後に A が出力され、そのすぐ後に ["A", "B", "C"] が出力される`

#### 説明
配列がシングルクウォートなこと以外は予想通り

```
Promise は wait3() → wait2() → wait1() の順で渡される。
wait1() → wait2() → wait3() で解決されるごとに logA() → logB() → logC() が実行される。
全 Promise が終了した時、それぞれの Promise の返り値が 渡された順（ABC）で配列として返される。
```

メモ

- 履行された値は、完了順に関係なく、渡されたプロミスの順番で、履行された値の配列となります。
[参考：MDN](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Promise/all#:~:text=%E5%B1%A5%E8%A1%8C%E3%81%95%E3%82%8C%E3%81%9F%E5%80%A4%E3%81%AF%E3%80%81%E5%AE%8C%E4%BA%86%E9%A0%86%E3%81%AB%E9%96%A2%E4%BF%82%E3%81%AA%E3%81%8F%E3%80%81%E6%B8%A1%E3%81%95%E3%82%8C%E3%81%9F%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%AE%E9%A0%86%E7%95%AA%E3%81%A7%E3%80%81%E5%B1%A5%E8%A1%8C%E3%81%95%E3%82%8C%E3%81%9F%E5%80%A4%E3%81%AE%E9%85%8D%E5%88%97%E3%81%A8%E3%81%AA%E3%82%8A%E3%81%BE%E3%81%99%E3%80%82)


### i3()
#### 回答

`1秒後に X が出力され、そのすぐ後に 42 が出力され、その1秒後に B が出力され、その2秒後（42出力から3秒後）に 0 が出力される`

#### 説明
配列がシングルクウォートなこと以外は予想通り

```
wait3() → wait2() → wait1() の順で Promise が開始され、wait1() 解決後の errY() で即時拒否を返して catch に入り log(e.message) と log(v) が実行される。
その後、wait2() が解決して logB() が実行され、最後に wait3() が解決して v=0 が書き換えられ、再度 log(v) が出力される。
```

メモ

- Promise.all() は、入力されたプロミスのいずれかが拒否されると直ちに拒否されます。
[参考：MDN](https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Promise/all#:~:text=Promise.all()%20%E3%81%AF%E3%80%81%E5%85%A5%E5%8A%9B%E3%81%95%E3%82%8C%E3%81%9F%E3%83%97%E3%83%AD%E3%83%9F%E3%82%B9%E3%81%AE%E3%81%84%E3%81%9A%E3%82%8C%E3%81%8B%E3%81%8C%E6%8B%92%E5%90%A6%E3%81%95%E3%82%8C%E3%82%8B%E3%81%A8%E7%9B%B4%E3%81%A1%E3%81%AB%E6%8B%92%E5%90%A6%E3%81%95%E3%82%8C%E3%81%BE%E3%81%99%E3%80%82)

### i4()
#### 回答

`11秒後に 5 が出力される`
これは、インクリメントと v の書き換えの間に wait2() があることで、後から実行される p1 がインクリメントするときに v が書き換わっていない。実質 p2 をやり直していることと同じになり、結局 p1 だけが反映されたような状態になる

#### 修正
インクリメントと v の書き換えを即座に行い、その前か後に wait2() を実行する
