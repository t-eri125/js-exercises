## 問題 13.2

以下の各関数 f3 から f12 までを実行すると何が出力されるか予想し実際に確認しなさい。 またその理由を 2、3 行のテキスト、図のいずれかまたは両方で説明しなさい。テキスト・図は f1 の解答例を参考にしなさい。

## 予想＆結果
### f3
#### 予想：
```
Cが出力され、0秒後に A が出力され、そのすぐ後に Error: X が出力される。
```

#### 確認結果＆理由：
予想通り。
```
wait0 の処理開始時に Promise は即解決される。
そこで、finally で先に logC が実行され、はじめの wait0 解決後に logA が実行され、その後 errX() が実行される。
ただし、 errX() が呼ばれる前に try/catch は終了しているため、エラーはキャッチされない。
```

### f4
#### 予想：
```
2秒後に A が出力され、そのすぐ後に 40 が出力され、さらに1秒後に B が出力される。
```

#### 確認結果＆理由：
予想と違った。実行順序を理解していなかった。
2秒後に A が出力され、その1秒後に B が出力され、すぐ後に 100 が出力される。

```
wait2 の処理開始時に Promise が作られる。
まず、wait2 解決後に then 内の logA が実行され 40 を返す。
次に2つ目の then は Promise を返すため、3つ目の then は待機。
2つ目の then で wait(1000) 解決後に logB が実行され 100 を返す。
最後に3つ目の then で、前の then で返された 100 が引数となり、log(v) が実行される。
```

### f5
#### 予想：
```
2秒後に A が出力され、その1秒後に B が出力され、すぐ後に 100 が出力される。
```

#### 確認結果＆理由：
予想と違った。Promiseの理解が甘かった。
1秒後に B が出力され、その1秒後（開始から2秒後）に A が出力され、すぐ後に 40 が出力される。

```
wait2 の処理開始時に Promise が作られる。
2つ目の then は関数ではなく即座に評価される Promise が引数のため、独立して wait1 の処理が開始する。

まず wait1 が先に解決し logB が実行され 100 を返す。
次に、wait2 解決後（wait1と同時並行）に 1つ目の then 内の logA が実行され 40 を返す。
最後に3つ目の then で、前実行の then で返された 40 が引数となり、log(v) が実行される。
```

### f6
#### 予想：
```
1秒後に A が出力され、その1秒後に B が出力され、さらに1秒後に C が出力される。
```

#### 確認結果＆理由：
予想通り

```
p定義時に wait1が開始し、wait1 解決後に logA が実行される。
p の Promise が解決されたとき、1つ目の p.then() wait1 の処理、2つ目の p.then() wait2 の処理がそれぞれ独立して開始する。
先に wait1 が解決され logB が出力され、その後 wait2 が解決され logC が出力される。
```

### f7
#### 予想：
```
1秒後に A が出力され、その1秒後に B が出力され、すぐ後に C が出力される。
```

#### 確認結果＆理由：
予想通り

```
p を定義した時点で wait1 、Promise の wait2 が独立して開始される。
先に p の wait1 が解決され logA が実行される。
wait2 解決後、p はすでに解決済みなので、1つ目の then 内で p.then(logB) が即座に実行される。
1つ目の then で Promise が返った後、2つ目の then で logC が実行される。
```

### f8
#### 予想：
```
1秒後に X が出力され、その後すぐに A が出力される。
```

#### 確認結果＆理由：
予想通り

```
wait1 解決後に errX が実行されエラーがキャッチされる。
エラーがキャッチされたため finallyで logA が実行されて終了する。
```

### f9
#### 予想：
```
1秒後に Y が出力され、その後すぐに A が出力される。
```

#### 確認結果＆理由：
予想通り。
```
wait1 解決後に 1つ目の then() で ()=>42 が実行され 42 が返されるが、特に何も起きない。
その後、2つ目の then() で errY が実行されエラーがキャッチされる。
エラーがキャッチされたため finallyで logA が実行されて終了する。
```

### f10
#### 予想：
```
1秒後に A が出力され、その後すぐに Y が出力される。
```

#### 確認結果＆理由：
予想どおり？
1秒後に A が出力される（その後すぐに errY のエラー結果が出力される）。
<br>then(r, c) と then(r).catch(c) は等しくない。
<br>（参考：「p391 Promise のcatch() メソッドは、第1 引数にnull を指定して、第2 引数にエラー処理のためのコールバックを指定してthen()を呼び出すのと同じ」）
```
wait1 解決後に 1つ目の then() で ()=>42 が実行され 42 が返されるが、特に何も起きない。
その後、2つ目の then() で errY が実行されエラーを投げるが、キャッチされないため第二引数 (e)=>{} は実行されない。（p.384 「Promiseが満たされて完了した」？）
2つ目のPromiseが満たされたため、finally で logA が実行される。
（最後に 未処理のままになったエラーがコンソールに出力される。）
```

### f11
#### 予想：
```
すぐに X が出力される。
```

#### 確認結果＆理由：
予想通り。
```
new Promise の executor 内で sample.errX() が実行される。
すぐに Promise が reject され、エラーがキャッチされ、log(e.message) が実行される
```

### f12
#### 予想：
```
何も出力されない（コンソールにエラーは表示される。）
```

#### 確認結果＆理由：
予想通り。
```
new Promise の executor 内で コールバック関数 setTimeout() が呼ばれ、Promise が即座に resolve される。
これでnew Promiseが終了してエラーはキャッチできなくなった後、 errX がエラーを投げる。
（最後に 未処理のままになったエラーがコンソールに出力される。）
```
