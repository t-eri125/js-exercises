## 問題 15.11-15.15 🖋

Slack や O365 の API は機密情報をヘッダーで指定する。パスやクエリでないのは何故かセキュリティの観点で記載しなさい。

**出題範囲: 15.11.1**

## 回答

機密情報を履歴に残さないため。
URL 履歴、ログファイルに残らず、URL を他人に共有してもアクセストークンがばれることはない。
またメソッドに関わらず認証情報を扱える利点もある。


#### 参考
APIキーをHTTPヘッダーに含める理由
    https://qiita.com/tetsuro-seki/items/7675b34acd46e707d716

見落としがちなURL正規化によるパストラバーサル
※ 問題とは直接関係しないが、URL の取り扱いに関する一般的な脆弱性
    https://gmo-cybersecurity.com/blog/url-path-traversal/

```
パストラバーサルは../のような文字列を含んだ文字列の正規化処理（normalization）を悪用して、アプリケーションが予期しない"領域"に対してアクセスを行う攻撃
```
