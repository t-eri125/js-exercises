## 問題 15.11-15.16 🖋️

オリジン間リソース共有（CORS）について、以下の問いに答えなさい。

1. クロスオリジンリクエストに制約が無かった場合、どのような問題が発生するか述べなさい
2. クロスオリジンリクエストで メソッド(`POST`/`GET`)やリクエストの内容によって Preflight リクエストの有無が異なるのは何故か、その理由を述べなさい

**出題範囲: 15.11.1**

## 回答

### 問1 
悪意のある Web サイトから、利用者がログイン中の別サービスに対して不正なリクエストが実行される危険性がある。
例えば、ログインした状態で悪意のあるサイトを開いてしまった場合、
- ブラウザに保存されている Cookie などの認証情報が、悪意のあるサイトから発生したリクエストに自動的に付与される
- さらに、レスポンス内容を悪意あるサイトの JS から読み取れるようになり、個人情報や機密情報が盗まれる
などの危険がある。

### 問2 
Preflight は [オリジン間リクエストがユーザーデータに影響を与える可能性があるような場合](https://developer.mozilla.org/ja/docs/Web/HTTP/Guides/CORS#%E3%83%97%E3%83%AA%E3%83%95%E3%83%A9%E3%82%A4%E3%83%88%E3%83%AA%E3%82%AF%E3%82%A8%E3%82%B9%E3%83%88:~:text=%E3%82%AA%E3%83%AA%E3%82%B8%E3%83%B3%E9%96%93%E3%83%AA%E3%82%AF%E3%82%A8%E3%82%B9%E3%83%88%E3%81%8C%E3%83%A6%E3%83%BC%E3%82%B6%E3%83%BC%E3%83%87%E3%83%BC%E3%82%BF%E3%81%AB%E5%BD%B1%E9%9F%BF%E3%82%92%E4%B8%8E%E3%81%88%E3%82%8B%E5%8F%AF%E8%83%BD%E6%80%A7%E3%81%8C%E3%81%82%E3%82%8B%E3%82%88%E3%81%86%E3%81%AA%E5%A0%B4%E5%90%88) に行われる。
つまり、サーバーやユーザーデータに与える影響の大きさによって有無が変わる。

[単純リクエストの条件](https://developer.mozilla.org/ja/docs/Web/HTTP/Guides/CORS#%E5%8D%98%E7%B4%94%E3%83%AA%E3%82%AF%E3%82%A8%E3%82%B9%E3%83%88:~:text=%E5%8D%98%E7%B4%94%E3%83%AA%E3%82%AF%E3%82%A8%E3%82%B9%E3%83%88%E3%81%AF%E3%80%81%E4%BB%A5%E4%B8%8B%E3%81%AE%E3%81%99%E3%81%B9%E3%81%A6%E3%81%AE%E6%9D%A1%E4%BB%B6%E3%82%92%E6%BA%80%E3%81%9F%E3%81%99%E3%82%82%E3%81%AE%E3%81%A7%E3%81%99%E3%80%82) を満たす GET や一部の POST などは、従来から HTML フォーム送信などで利用されてきた比較的影響の小さい通信であるため、Preflight リクエストは行われない。
一方で、
・PUT や DELETE メソッド
・Authorization ヘッダーを含むリクエスト
・application/json を用いた通信
などは、サーバーの状態変更や機密情報の取り扱いにつながる可能性が高い。



```
メモ：そもそものクロスオリジンの制約

スキーム（http / https）、ホスト名（ドメイン）、ポート番号がすべて一致する場合のみJavaScript から自由にリソースへアクセスできる。

CORS レスポンスヘッダーを返さない限り
・JavaScript からレスポンス内容を読み取れない
・Cookie や認証情報を含む通信が制限される
・一部の HTTP メソッドやヘッダーが使用できない
```
